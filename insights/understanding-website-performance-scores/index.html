Understanding Your Website Score: What Do Those Numbers Actually Mean?

By SZARA · Design and technology resources

Understand Lighthouse and PageSpeed Insights scores, performance metrics, Core Web Vitals, accessibility and technical SEO.

Quick answer

Lighthouse scores four separate categories from 0 to 100. Performance combines measured loading and responsiveness indicators; these are diagnostic scores, not guarantees of rankings, accessibility compliance or sales.

Explore website assessments

When you run a website test, a red or amber score can look alarming. But before making changes, it helps to understand what the numbers measure and what they do not.

Four separate scores

  • Performance: how efficiently the page loads and displays content under test conditions.
  • Accessibility: selected checks for issues such as contrast, accessible names and form labels. Automated checks cannot establish full accessibility compliance.
  • Best practices: selected modern development, reliability and security checks. This is not a comprehensive security audit.
  • SEO: basic technical requirements for search discovery. It does not assess all ranking factors, keyword competition or reputation.

Scores from 0 to 49 are generally poor, 50 to 89 need improvement, and 90 to 100 are good. Each category is separate; there is no single all-purpose website score.

How the performance score is calculated

Lighthouse converts individual measurements to scores and combines them using weights. In the published Lighthouse performance scoring model:

  • Total Blocking Time (30%): time during loading when long browser tasks can interfere with responsiveness.
  • Largest Contentful Paint (25%): how long the main visible content element takes to render.
  • Cumulative Layout Shift (25%): unexpected movement of visible content, such as a button shifting just before you tap it.
  • First Contentful Paint (10%): when the first visible content appears.
  • Speed Index (10%): how quickly the visible page fills in.

These weights can change with Lighthouse versions. Refer to the official scoring documentation for the current model. A raw measurement is not itself a score; Lighthouse uses scoring curves.

Lab tests versus real visitor experiences

PageSpeed Insights combines a controlled Lighthouse lab test with real-world Chrome User Experience Report data where available. Lab scores can vary between runs. A newly launched or low-traffic website may not have enough field data.

Core Web Vitals are real-world measures of loading, responsiveness and stability: LCP, Interaction to Next Paint (INP), and CLS. Good thresholds are LCP at or below 2.5 seconds, INP at or below 200 milliseconds and CLS at or below 0.1, evaluated at the 75th percentile of visits. TBT is a useful lab diagnostic, not a replacement for real-world INP.

What affects the numbers?

Oversized images, poorly timed scripts, render-blocking stylesheets, slow server responses and layout changes can all contribute. A low score indicates where to investigate; it does not prove you need a new website. A score of 100 does not prove every customer journey works.

Try PageSpeed Insights yourself and read Google's Core Web Vitals guide. Compare representative pages, not just the homepage, and repeat tests under comparable conditions.
